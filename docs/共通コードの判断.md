# 共通コードの判断（cc-park から写したコード）

2026-11-21 · 第 4 段階「共通コードの切り出し判断」の記録

## 決めたこと

**共通パッケージには切り出さず、cc-park から写して使うやり方を続ける。**
代わりに、写したファイルと写し元のずれを `npm run copies:check -- <cc-park のディレクトリ>` でいつでも確かめられるようにし、
使っていない写しは消す。

## 判断の材料（v0.3.1 の時点）

| 項目 | 値 |
| --- | --- |
| 写したファイル（テストを含む） | 44（使っていなかった `StatusBadge` / `aaBitmap` / `attention` の 5 ファイルは消した） |
| 写したコード（テストを除く） | 約 2,500 行 |
| cuse 独自のコード（テストを除く） | 約 6,600 行 |
| 写し元と同じまま | 36 |
| cuse で変えたもの | 8（どれも足しただけ。消したり意味を変えたりはしていない） |
| 写した後の cc-park の変更 | なし（v0.25.0 @ `d1f0f2d` のまま） |

cuse で変えたもの（cc-park に戻す候補）:

| ファイル | 変えたこと | cc-park にも要るか |
| --- | --- | --- |
| `src/core/runCommand.ts` | 子プロセスへ渡す環境変数（`env`）。失敗の理由を標準エラーから取り、コマンド全体を出さない | 標準エラーから取る方は cc-park にもあると良い（失敗の理由が分かりやすくなる） |
| `src/types/agent.ts` / `src/core/normalizeAgent.ts` | `claude agents --json` の `waitingFor` を読む | cc-park にもあると、承認待ちと入力待ちを正確に見分けられる |
| `src/shared/parseTranscript.ts` | 最後の assistant 発言・最後の `cwd` を取る関数 | 今の cc-park には要らない |
| `src/core/agentsDebug.ts` ほか | 記録の置き場所を `~/.cuse/` にした | 要らない（cuse 固有） |

## 切り出さない理由

- **ずれが小さく、足しただけ**: 写したものの 8 割は今も同じで、変えたものも追加だけ。取り込み直す手間は小さい。
- **cc-park が動いていない**: 写した後、cc-park 側の変更は 0。共通化しても、すぐに得るものが無い。
- **切り出すと手間が増える**: 共通パッケージを作ると、3 つ目のリポジトリ・npm への公開・2 つのアプリの版合わせが要る。
  cuse は `.app` だけを配り、`--no-asar` で依存を最小にしている（`meow` と `node-pty` だけ）ので、依存を増やしたくない。
- **それぞれの道具が壊れても、もう片方を巻き込まない**: 写しておけば、cc-park の変更が cuse の指揮役（起動・停止を伴う）を
  知らないうちに変えることがない。企画書の「安全の境界がはっきりする」という切り出しの理由とも合う。

## 見直すとき

次のどれかが起きたら、もう一度判断する。

- cc-park で写したファイルが変わり、取り込みが続けて要るようになった（`copies:check` で「cuse で変えた」以外のずれが増える）
- `claude agents --json` や transcript の形が変わり、両方で同じ直しを何度もすることになった
- 3 つ目の道具が同じコードを使いたくなった

## 写しの扱い

- 写したファイルの先頭の「写し元: cc-park `<パス>` @ `<コミット>`」は消さない。`copies:check` はこの行で写し元を見つける。
- 写したファイルを直すときは、先頭の行を残し、PR に「cc-park にも要る修正か」を書く（`CLAUDE.md`）。
- cc-park を取り込み直したら、先頭の行のコミットを取り込んだものに書き換える。
