# cuse 企画書（単体ツール版）

Nov 21, 2026 · @Naoki Ishimura

## 概要

cuse は、1 つの Claude Code セッション（以下「指揮役」）が、同じマシンで動くほかの Claude Code セッションを起動し、見守り、指示し、結果を回収し、止められるようにする単体の CLI ツールです。muse と同じく、指揮役はマシンに 1 人だけ置き、指揮役自身は作業せず、作業はすべて配下のセッションに任せます。11/17 の企画書では cc-park の 1 モードとして考えていましたが、cc-park から切り離して独立したリポジトリ・パッケージとして作ります。

**切り出す理由**

- **役割が違う**: cc-park は人がセッションを「見る」道具、cuse は Claude がセッションを「動かす」道具。使う人も、壊れたときの影響も違う。
- **cc-park なしで使える**: cc-park を入れていなくても `npm i -g` だけで指揮役を動かせる。
- **リリースを分けられる**: cuse は Claude Code の新しい機能（background セッション、cross-session messaging）に追随して頻繁に変わる。cc-park の安定版を巻き込まずに出せる。
- **安全の境界がはっきりする**: 起動・停止という影響の大きい操作を、小さく読みやすいコードに閉じ込められる。

前回の企画書（[cc-park cuse mode 企画書](https://claude.ai/artifact/YPvMy69fJG8qckLoVGHGei)）の目的・利用シーン・安全設計はほぼそのまま引き継ぎ、cc-park に頼っていた部分（状態の読み取り、台帳、画面）を cuse 自身が持つ形に組み直します。

## 目的と、やらないこと

狙いは、人が「指揮役とだけ話せば、並列の仕事が回る」状態を、cc-park がなくてもつくれることです。

**目的**

1. 指揮役が、大きな依頼を分けて配下セッションを名前付きで起動できる。
2. 指揮役が、配下の状態（作業中・入力待ち・承認待ち・完了・失敗）を正しく知り、完了を待てる。
3. 指揮役が、配下に追加の指示を出し、結果（最後の報告と変更の差分）を回収してレビューできる。
4. 人にしかできないこと（権限の承認、方針の判断）だけが、理由つきで人に回ってくる。
5. 人が cuse のウィンドウ 1 つで「指揮役の配下がどう動き、何が自分を待っているか」を見渡せる。

**やらないこと**

- 配下の権限プロンプトを指揮役や cuse が代わりに承認すること。
- 作業の分割や計画のロジックを cuse に持たせること。考えるのは指揮役の Claude で、cuse は道具に徹する。
- 配下のブランチを main へマージすること。取り込みは人が PR で判断する。
- 別のマシンやクラウドのセッションの管理（初期版はこのマシンだけ）。
- 端末の TUI と Web UI。画面はデスクトップアプリ（GUI）だけにする。常駐のミニ表示やメニューバー表示は cc-park に任せる。
- Claude Code の agent view の作り直し。人が配下に直接返信したいときは agent view や `claude attach` を使う。

## 利用シーン

人が指揮役に大きめの依頼を 1 つ出し、後は承認と最終判断だけをする、という流れは前回と同じです。違いは、入口が `cc-park cuse` ではなく `cuse` になり、人は cuse のウィンドウの中央で指揮役とだけ話し、配下の様子は左で見る点です。

1. 人がリポジトリで `cuse start` を実行し、指揮役に「通知設定の整理、README の更新、テストの追加を並行で。終わったら差分をまとめて見せて」と頼む。
2. 指揮役が `cuse spawn` で `notify-settings` `readme` `tests` の 3 セッションを起動する。それぞれ別の worktree で編集する。
3. 指揮役が `cuse wait` で待つ。人は cuse のウィンドウの左で、3 つの配下の進み具合を見る。
4. `tests` が `npm test` の実行承認で止まる。`cuse wait` が「`tests` が Bash: npm test の承認待ち」を返し、指揮役はそれを人に伝える。cuse は OS 通知も出す。人は左の tests を開き、中央に出た Claude Code で承認する。
5. `readme` が入力待ちで止まる。指揮役は `cuse output readme` で質問を読み、方針の範囲内なら `SendMessage` で答える。方針に関わる場合は人に聞く。
6. 3 つとも完了したら、指揮役が `cuse review` で各 worktree の差分と最後の報告を集め、人にまとめて報告する。直しが要る配下には指示を戻す。
7. 人が各 PR をマージする。指揮役が `cuse kill` と `cuse clean` で配下を片付ける。

ほかに、手で動かしているセッションを指揮役に「観察だけ」させる使い方もあります。例えば「今どれが私を待っている？ 優先順に並べて」と聞く場合です。

## 機能一覧

指揮役が Bash から呼ぶコマンド 10 個と、人が使うデスクトップアプリ（`cuse app`）を用意します。名前と引数は muse のコマンドにそろえ、指揮役向けはすべて `--json` に対応し、配下は名前で指します。muse の `attach` / `dashboard` / `monitor` は、このアプリ 1 つにまとめます。

| コマンド | muse の対応 | 動き |
| --- | --- | --- |
| `start [--cwd]` | `start` | 指揮役を起動する。すでに指揮役がいれば新しく起動せず、その指揮役を開く。名前は `cuse-leader`、cuse スキルと指揮役の心得を読み込み、編集系ツールを外した状態で起動し、cuse のウィンドウを開く |
| app | attach / dashboard / monitor | cuse のウィンドウ（GUI）を開く。左に配下、中央に指揮役の会話、右にプレビュー。人の依頼と相談はここだけ |
| `status` | `status` | 配下の数、状態ごとの件数、人の対応が要るものを返す |
| `agents [--all]` | `agents` | 配下（`--all` で全セッション）の状態、`waitingFor`、承認待ちのツール、最後の指示、コンテキスト使用率 |
| `spawn "<タスク>" <名前> [--cwd --agent --model]` | `spawn` | `claude --bg --name` で起動し、指揮役の配下として台帳に記録 |
| `prompt <名前> "<指示>"` | `prompt` | 配下が終わっていれば `claude --resume <UUID> --bg` で続きを頼む。動いていれば「`SendMessage` で @<名前> に送る」よう指揮役に返す |
| `wait <名前…> [--until idle\|attention\|done] [--timeout]` | （`monitor`） | 条件が成り立つまで待ち、「誰が何のために止まったか」を返す |
| `output <名前> [--lines N]` | `output` | 最後の報告（transcript の最後の assistant 発言）と `claude logs` の末尾 |
| `review <名前>` | `review` | worktree のブランチ、`git diff --stat`、未 commit / 未 push、PR、最後の報告をまとめる |
| `kill <名前> --reason "<理由>"` | `kill` | `claude stop` で止め、理由を台帳に残す |
| `clean` | — | 完了した配下を `claude rm` で片付ける。未 commit / 未 push があるものは残す |

**台帳**: 「誰が指揮役で、どの配下を起動したか」は `claude agents --json` に載らないため、cuse が `~/.cuse/ledger.json` に記録します。項目は指揮役の sessionId、配下の名前・短縮 ID・sessionId、タスク、worktree、起動時刻、終了理由です。形式は公開し、他のツール（cc-park など）が読めるようにします。

**指揮役は 1 人**: 台帳に登録できる指揮役はマシンに 1 人だけです。

- `cuse start` は、登録済みの指揮役が動いていればその画面を開く。止まっていれば `claude --resume` で同じ会話を再開する。作り直すときだけ `--new` を付ける（前の指揮役は止め、配下は新しい指揮役が引き継ぐ）。
- `cuse start` は指揮役にだけ専用のトークンを環境変数で渡す。`spawn` / `prompt` / `kill` / `clean` はそのトークンがあるときだけ動く。配下には渡さないので、配下が別の配下を作ることはできない。
- 別のリポジトリの作業も、指揮役を増やさず `spawn --cwd` で配下に回す。
- 人の操作（GUI の止める・片付ける）はトークンなしで使える。

**作業は配下に任せる**: 指揮役は計画・分担・確認・報告だけを受け持ち、コードの編集や作業のためのコマンド実行はすべて配下が行います。

- `cuse start` は指揮役を `--disallowedTools` で Edit / Write / NotebookEdit を外して起動し、ファイルを書けないようにする。
- Bash は `cuse` コマンドと読み取り（`git diff`、`git log` など）だけを許す権限設定を同梱する（案）。Bash 経由の書き込みは設定だけでは止めきれないので、心得でも縛る。
- 小さな作業でも 1 つの配下に渡す。指揮役の心得に「自分で直さず、配下に戻す」を入れる。
- 指揮役の会話には配下の報告と差分の要約しか溜まらないので、長い依頼でも指揮役のコンテキストが溢れにくい。

**指揮役への渡し方**: コマンドの使い方と心得をまとめた Claude Code のスキル（`cuse` スキル）を同梱します。`cuse start` が読み込んだ状態で起動し、`cuse install-skill` で普段のセッションにも入れられます。後の段階で、同じ機能を MCP サーバーとしても出します。

## 全体構成

指揮役が考え、cuse が指揮役の目と手になり、配下は Claude Code の background セッションとして動きます。前回 cc-park が担っていた役は、すべて cuse に移ります。

&#91;embedded content: cuse の全体構成 · 人・指揮役・cuse・配下・台帳・cc-park\]

指示を届ける経路は 2 つです。動いている配下には指揮役が `SendMessage` で直接送り、止まった配下には cuse が `claude --resume` で続きを頼みます。cc-park は台帳を読むだけで、なくても cuse は動きます。

**cuse の中身**（前回 cc-park の既存コードに頼っていた部分）

- **状態の読み取り**: `claude agents --json --all` の `state` / `status` / `waitingFor` と、transcript から読む承認待ちのツール・最後の指示・コンテキスト使用率を合わせる。
- **変化の検出**: 前回の状態と比べて「承認待ちになった」「完了した」を拾い、`wait` の応答と OS 通知に使う。
- **台帳**: 指揮役と配下の対応、終了理由を記録する。書き込みは一時ファイル経由で壊れないようにする。

## 画面（GUI）

画面はデスクトップアプリ（GUI）だけにし、端末の TUI と Web UI は作りません。muse の `attach` / `dashboard` / `monitor` に当たるものを、cuse のウィンドウ 1 つにまとめます。人はこのウィンドウの中で指揮役とだけ話します。

| 場所 | 中身 | muse の対応 |
| --- | --- | --- |
| 上端のバー | 指揮役の状態、配下数、対応待ち数、コンテキスト使用率。健全性の警告（止まっている配下、長い承認待ち、上限に近い同時実行数）もここに出す | `monitor` |
| 左 | 配下（サブセッション）の一覧。承認待ちが先頭。各カードに Clawd の AA、名前、状態、経過時間、最後の動き。クリックで詳細、「開く」でその配下の会話を中央に出す（承認用） | `dashboard` |
| 中央 | 指揮役の会話。アプリの中に端末を埋め込み（xterm.js + node-pty）、`claude attach cuse-leader` をそのまま動かす。上部に指揮役の大きめの Clawd | `attach` |
| 右 | プレビューエリア。セッションに出たファイル・差分・画像・Web サイト | — |

端末を埋め込むので、中央の見た目と操作は Claude Code そのものです。配下の承認も、左で配下を「開く」と中央にその配下の Claude Code が出て、人がそこで承認します（タブで指揮役に戻る）。

**プレビューエリア**

セッションの中で表示されたファイルや Web サイトを、そのまま右側で見られるようにします。指揮役が「差分を右に出しました」と言えば、人は会話から目を離さずに中身を確かめられます。

| 拾うもの | どこから | プレビューでの見せ方 |
| --- | --- | --- |
| 読んだファイル | transcript の Read ツールの呼び出し | シンタックス色付きで表示。Markdown は整形して表示 |
| 変えたファイル | 配下の Edit / Write、`git diff` | その配下の worktree での差分（並べて比べる表示と 1 列表示を切替） |
| 画像 | Read した画像、スクリーンショット | そのまま表示。拡大・縮小できる |
| Web サイト | WebFetch の URL、会話に出た `localhost` などの URL | アプリ内の隔離したブラウザ表示で開く。普段のブラウザで開くボタンも置く |

- 既定では指揮役のセッションに出たものを追いかけ、新しいものが出たら切り替える。「固定」で追いかけを止められる。
- 左で配下を選ぶと、その配下のセッションに出たファイルや URL に切り替わる。
- 上部にタブ、下部に表示履歴を置き、前に出たものに戻れる。幅が狭いときはプレビューを畳める。
- 安全のため、セッションに出ていないファイルや URL は開かない。Web サイトは Node 連携なし・専用のセッション領域で開き、アプリ本体やファイルに触れさせない。`.env` など秘密を含みそうなファイルは伏せて出し、クリックでだけ中身を開く。

**Clawd のアスキーアート**

- 左の各配下のカードに、Claude Code の起動バナーのマーク（Clawd）を AA で出す。muse と同じくメインセッションにも出し、指揮役の AA は中央の上部に配下より大きく、「指揮役」の印と状態を添えて出す。
- 状態は手・足の動きと色で表す。承認待ちは右手が上下（黄）、作業中は足が動く（シアン）、完了直後は両手（明るい緑）、入力待ちと停止は静止（灰）。
- サブエージェントが走っている配下には、AA の横にミニキャラクターを並べる。
- AA とコマは cc-park と同じ定義を使い、描き方も cc-park の renderer に合わせる。OS の「視差効果を減らす」設定がオンなら動きを止める。

**人の動き方**

1. `cuse start` で指揮役を起動する。cuse のウィンドウが開き、中央に指揮役が出る。
2. 依頼は中央の指揮役にだけ出す。配下には直接指示しない。
3. 指揮役が配下を起動すると、左に Clawd が並んで動き出す。
4. 指揮役が差分やサイトを確かめると、右のプレビューにその中身が出る。
5. 左で右手を振っている（承認待ちの）配下があれば「開く」を押し、中央に出たその配下で承認して、タブで指揮役に戻る。

**置かないもの**: 承認ボタン（承認は Claude Code の画面で人が行う）、配下への指示欄、画面からの `spawn`（指示と起動はすべて指揮役を通す）。端末の TUI と Web UI。常駐のミニ表示やメニューバー表示は cc-park の領分とし、cuse には入れない。

**SSH 先での使い方**: GUI だけにしたため、人が画面を見るにはそのマシンのデスクトップが要ります。指揮役が使う CLI（`spawn` など）は SSH 先でも動きます。

**入れる時期**: 第 1 段階は上端のバーと左の一覧だけの読み取り専用ウィンドウ、第 2 段階で中央の埋め込み端末（指揮役と配下を開く）、第 3 段階で右のプレビューと詳細表示を入れます。

## cc-park との関係

cuse と cc-park はお互いを必要とせず、台帳ファイルだけでゆるくつながります。cuse が書き、cc-park はあれば読む、の一方向です。

| 項目 | cuse | cc-park |
| --- | --- | --- |
| 使う人 | 指揮役の Claude（人は cuse のウィンドウを使う） | 人 |
| セッションへの操作 | 起動・指示・停止・片付け | 一覧・通知・画面への移動・停止・予約起動（今のまま） |
| 台帳 `~/.cuse/ledger.json` | 書く | 読む（あれば） |
| 画面 | デスクトップアプリ（3 列、指揮役と配下を操作） | GUI / TUI のキャラクター表示 |

**cc-park 側の変更**（cuse の第 2 段階以降、cc-park の別リリースで）

- 台帳があれば読み、「指揮役と配下のグループ」を足す。指揮役に `[cuse]` の印、配下を字下げ、終わった配下は薄く残す（前回企画の「GUI / TUI での見せ方」をそのまま使う）。
- 配下の「入力待ち」は指揮役が答えるので、既定では通知しない。
- cuse が入っていなければ何も変わらない。cc-park に cuse への依存は足さない。

**コードの共有**: transcript の読み取り（`parseTranscript` / `readSessionMeta`）と `claude agents --json` の解釈（`fetchAgents`）、それに Clawd の AA と状態ごとのコマは両方に要ります。初期版では cc-park から写して cuse に持ち、差が出始めたら共通パッケージ（仮称 `@naoki/claude-sessions`）に切り出すかを決めます。

## 技術選定と配布

cc-park と同じ TypeScript + Node.js で作り、npm で配ります。写してくるコードがそのまま動き、Claude Code を使う人はほぼ Node.js を入れているからです。

| 項目 | 案 |
| --- | --- |
| リポジトリ | `NaokiIshimura/cuse`（新規、公開） |
| パッケージ名 | `cuse`。npm で取れなければ `cuse-cli` か `@naoki/cuse` |
| 言語・実行環境 | TypeScript、Node.js 20 以上 |
| 外部依存 | アプリは Electron + React（cc-park と同じ）、中央の埋め込み端末に xterm.js と node-pty。CLI 部分は引数解析だけ。アプリは cc-park と同じく .app でも配る |
| `claude` の実行 | cc-park の `CommandRunner` と同じ形で差し替えられるようにし、テストでは偽物を使う |
| テスト | 単体テスト、型チェック、ビルドを CI で回す。transcript と `claude agents --json` は実物の見本を固定して使う |
| 同梱物 | `cuse` スキル（SKILL.md）、指揮役の心得、台帳の JSON Schema |
| 対応 OS | macOS を先に。Linux はデスクトップ環境があれば対応、Windows は後で検討 |

後の段階で、同じコマンドを MCP サーバー（`cuse mcp`）としても出し、Claude Code のプラグインとしてスキルと一緒に入れられるようにします。

## 安全設計

原則は前回と同じく「承認は必ず人に戻す」「配下の権限は指揮役より広くしない」の 2 つです。

| 危険 | 対策 |
| --- | --- |
| 配下の権限プロンプトを指揮役が勝手に通す | 承認するコマンドを置かない。`wait` は承認待ちを「人に回すもの」として返し、cuse が OS 通知を出す |
| 指揮役が 2 人立ち、配下を取り合う | `cuse start` は 2 人目を起動しない。操作系コマンドは指揮役のトークンがないと動かず、配下が孫を作ることもない |
| 配下が指揮役より強い権限で動く | `spawn` に `--dangerously-skip-permissions` を渡さない。権限モードは指揮役と同じか弱いものだけ |
| 配下を起動しすぎて利用枠を使い切る | 同時に動かせる配下の上限を設定で持ち、既定は 3。超える `spawn` は断る |
| 指揮役と配下が終わらないやり取りを続ける | 配下 1 つあたりの `prompt` 回数に上限 |
| 作業中の変更を片付けで消す | `clean` は未 commit / 未 push の worktree を残す。`kill` は止めるだけ |
| 配下が main を書き換える | background セッションは main / master へ push しない。取り込みは人が PR で行う |
| 人の手で動かしているセッションを指揮役が止める | `kill` / `clean` できるのは台帳に載った配下だけ |

指揮役の心得（`cuse start` で渡す文）には、承認待ちと方針の判断は人に聞くこと、自分で拒否された操作を配下にやらせないこと、配下の報告は差分を見てから伝えること、の 3 つを入れます。

## リスクと未確認事項

いちばん大きい不確かさは前回と同じく、動いている配下へ CLI から直接文を届けられないことです。届ける役は指揮役の `SendMessage` に任せます。

- [ ] **状態の読み取りを自前で持つ負担**: cc-park にあった transcript の解釈と「解釈できない値を見張る」仕組みを cuse でも保守する。仕様変更のたびに 2 か所直すことになる。
- [ ] **通知の二重化**: cc-park と cuse の両方が入っていると、承認待ちの通知が 2 つ出る。cuse の通知を切れる設定を用意する。
- [ ] **受信の保留**: 指揮役と配下で権限モードの種類が違うとメッセージが保留される。両者を同じ種類にそろえる。
- [ ] **配下の自動停止**: 放置された background セッションは止められる。`wait` と `prompt` は「止まっていたら resume で再開」を前提にする。
- [ ] **名前の重複**: 同じ名前の生きたセッションがあると別名に変えられる。`spawn` は本当の名前と ID を台帳に記録する。
- [ ] **対応バージョン**: background セッションは v2.1.139 以降、cross-session messaging は v2.1.224 以降、名前での `attach` / `logs` は v2.1.290 以降。`cuse start` で確かめる。
- [ ] **worktree が作られない場合**: git リポジトリでない場所では配下同士が同じファイルを書き合う。`spawn` は警告を返す。

* [ ] **埋め込み端末**: node-pty はネイティブモジュールで、Electron のバージョンに合わせたビルドが要る。`claude attach` を埋め込んだときのキー操作や色を、第 2 段階の最初に試して確かめる。
* [ ] **cc-park との重なり**: どちらも Electron アプリになる。cuse は「指揮役と配下を操作するウィンドウ」、cc-park は「全セッションを眺める常駐ウィンドウ」と役を分ける。
* [ ] **SSH 先での利用**: GUI だけなので、画面を見るにはそのマシンのデスクトップが要る。指揮役向けの CLI は動く。

## 決めてほしいこと

次の 6 点が決まれば、第 1 段階に着手できます。括弧内はこの企画書での案です。

- [ ] リポジトリ名と npm のパッケージ名（案: `NaokiIshimura/cuse`、`cuse`）
- [ ] 共通コードの扱い（案: 最初は cc-park から写す。共通パッケージ化は第 3 段階の後に判断）
- [ ] 同時に動かす配下の上限の既定値（案: 3）
- [ ] cc-park 側の台帳対応をいつやるか（案: cuse の第 2 段階のリリースに合わせて）
